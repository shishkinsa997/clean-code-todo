# Инструкция для AI-ревьюера

## Цель

Проанализируй код проекта clean-code-todo (`app.js`, `index.html`, `style.css`) и найди проблемы из модуля Clean Code: мёртвый код, дублирование обработчиков и логики, непонятные имена, комментарии-пересказы, функции, которые не читаются целиком. Дай замечания с обоснованием, чтобы автор решил, что исправлять.

## Границы

- Проверяй только `app.js`, `index.html`, `style.css`.
- Не проверяй `.github/`, `node_modules/`, `package.json`, конфиги ESLint/Prettier/Husky — это настройка инструментов, не рефакторинг.
- Не редактируй файлы. Только анализ и объяснения.
- Не предлагай фреймворки, сборщики, новые зависимости.
- Не применяй DRY/KISS/YAGNI формально — каждое замечание должно решать конкретную проблему.
- Не дроби функции только из-за длины и не объединяй код только из-за сходства.
- Не комментируй то, что уже исправлено: делегирование событий, `createDomElement`, переименования, удаление `ajaxRequest` — это принятые решения.

## Критерий готовности

Ревью закончено, когда:

- пройдены все пять категорий из задания;
- по каждой проблеме указано место в коде, описание, условие проявления и способ проверки;
- нет общих фраз вроде «улучшить читаемость» без конкретики;
- замечания сгруппированы по категориям и отсортированы по важности.

## Формат вывода

Отчёт в файле `review-report.md` на русском. Каждое замечание — четыре части:

- **Место:** файл и строка (например, `app.js:15`).
- **Проблема:** что не так и почему это проблема.
- **Условие:** при каких обстоятельствах она проявляется.
- **Проверка:** как убедиться, что исправление сработало.

Структура отчёта:

```markdown
# Review Report

## 1. Мёртвый код

…

## 2. Дублирование обработчиков

…

## 3. Дублирование логики

…

## 4. Имена переменных и функций

…

## 5. Комментарии

…

## 6. Длинные функции

…
```
